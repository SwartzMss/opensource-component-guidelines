# 发布前合规检查清单

## 文档目的

本篇提供一个面向对外交付场景的发布前检查清单，帮助团队在软件发布、交付、上线前完成基础开源合规核对。

## 适用场景

- 客户端安装包发布
- 容器镜像发布
- SDK 或插件包交付
- 私有化部署包交付
- 其他包含第三方开源组件的发布物

## 发布物识别

- [ ] 已明确本次发布物名称和版本
- [ ] 已明确发布物交付形式
- [ ] 已明确是否对外提供安装包、镜像、源码包或离线包
- [ ] 已明确本次发布涉及哪些第三方组件

## 依赖清单检查

- [ ] 第三方组件清单完整
- [ ] 组件名称和版本准确
- [ ] 组件来源信息可追溯
- [ ] 新增依赖已纳入台账
- [ ] 本次升级组件已重新核对 License

## License 信息检查

- [ ] 所有第三方组件 License 已识别
- [ ] License 信息来自正式声明
- [ ] 双 License 或复杂 License 已单独评估
- [ ] 高风险 License 已完成审核
- [ ] 组件升级后无未处理的 License 变化

## 分发义务检查

- [ ] 需要保留的版权声明已保留
- [ ] 需要附带的 License 文本已准备
- [ ] 需要关注的 NOTICE 文件已处理
- [ ] 如适用，已标记对第三方代码的修改
- [ ] 如适用，已满足源码提供或相关开放义务

## 源码修改检查

- [ ] 已确认是否修改过第三方源码
- [ ] 已记录修改范围和修改责任人
- [ ] 已确认修改行为是否触发额外义务
- [ ] 已确认被复制进仓库的第三方代码都已补齐来源和声明

## 发布包内容检查

- [ ] 第三方声明文件已随发布物提供
- [ ] 相关 License 正文已随发布物提供
- [ ] 发布包中的声明内容与实际依赖一致
- [ ] 不存在来源不清或未经审批的第三方代码

## 高风险场景复核

以下任一项命中时，建议在发布前做专项复核：

- [ ] 使用 GPL、AGPL 或其他强 Copyleft License 组件
- [ ] 使用 LGPL、MPL 等需结合接入方式判断的组件
- [ ] 发布物中包含修改过的第三方源码
- [ ] 产品为闭源商业交付物
- [ ] 发布物面向客户或公众大规模分发

## 最终确认

- [ ] 研发负责人确认完成
- [ ] 如需要，法务或合规角色确认完成
- [ ] 本次发布留存了检查记录
