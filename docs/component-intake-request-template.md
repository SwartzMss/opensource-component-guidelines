# 依赖引入申请模板

## 文档目的

本篇提供一个轻量的依赖引入申请模板，适合作为团队内部在引入新开源组件前的记录或审批输入。

## 适用场景

- 新增第三方依赖前
- 引入新的开源 SDK 前
- 复制第三方源码前
- 高风险组件升级前

## 模板

```text
依赖引入申请

一、基础信息
1. 组件名称：
2. 组件版本：
3. 官方来源：
4. License 类型：
5. 申请人：
6. 申请日期：

二、引入背景
1. 需要解决的问题：
2. 为什么必须引入该组件：
3. 是否评估过替代方案：

三、使用方式
1. 使用范围：
2. 使用模块：
3. 是否仅内部使用：
4. 是否会对外交付或分发：
5. 是否会修改第三方源码：
6. 是否会复制第三方代码到本仓库：

四、风险初筛
1. 社区维护状态：
2. 已知安全风险：
3. License 风险判断：
4. 是否涉及高风险 License：

五、结论
1. 是否建议引入：
2. 需要补充的合规动作：
3. 审核意见：
```

## 简化版字段

如果团队希望先快速落地，也可以只保留最小字段：

- 组件名称
- 版本
- 来源
- License
- 使用方式
- 是否对外交付
- 是否修改源码
- 结论

## 使用建议

- 宽松型 License 的常规依赖可走轻量记录流程
- 涉及 GPL、AGPL、LGPL、MPL 等组件时，建议补充更完整的说明
- 如果组件最终进入对外发布物，应与发布前合规检查一起留档
